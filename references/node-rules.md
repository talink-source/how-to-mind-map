# Node rules

Read this before writing or reviewing any part of a map.

## What a node is

A node is a job someone decides to take on. It starts with a verb and names what gets done: "Build a cohort retention table," "Write the screener," "Run a holdout on the largest paid channel."

Each child answers "how?" for its parent. Read any parent and its children aloud as "To [parent], [child 1], [child 2] and [child 3]." If the sentence doesn't hold, the children are wrong.

## What a node is not

| Not a node | Where it goes instead |
|---|---|
| A question to ask in an interview or survey ("Ask: when did this last happen?") | A note on the task that produces the guide or survey ("Write the interview guide") |
| A checklist item, criterion or rule ("Keep it under ten words") | A note on the task it governs |
| A table, template or example | A note |
| A concept or principle ("Retention is a leaky bucket") | Nowhere. Leave it out; the structure should make the point |
| The keystrokes of one task ("Open the spreadsheet," "Add a column") | Nothing. The task above it is already the bottom. |
| A source or author name | Nothing. Never put names on nodes. |

## When to stop

A branch is done when its last node is a task someone could put on their calendar today and do without asking "how?" It has a clear output: a document, a list, a decision, a sent message, a live page, a number.

Keep going when the last node is still a project. Signs of a project: it would take more than a day, it needs other people to finish, or a competent person would still ask "where do I start?" "Audit current channels, creative and spend" is a project. Five levels of real work sit under it.

## Depth comes from the work

Go deeper only where the work has real sub-jobs. Never split one task into its steps to add a level, and never add a parent with a single child just to lengthen a chain. A map that is honestly 10 levels deep beats one stretched to 15.

The deepest levels are where the valuable know-how sits. When the expert says "I don't have a framework for that," stop and capture it: that gap is often the most useful node on the map.

## Whose work it is

Settle the point of view before writing a single node and keep it everywhere.

- Mapping how someone helps other companies: nodes are work done on "the company," its customers and its team. "Your" only ever means the operator.
- Mapping someone's own business: nodes are work the business does for its own customers.

Customer-facing wording inside notes (survey questions, interview prompts, messaging templates) keeps the voice the customer would hear.

## Quality bar for every node

- Specific: names the real object (the screener, the cohort table, the referral ask), not a category of activity.
- Actionable: a practitioner could start it today.
- Dense: the notes carry the specifics a practitioner would save: criteria, scripts, thresholds, benchmarks, examples.
- In context: the chain above it explains why it matters. A node that only makes sense on its own is in the wrong place.
- No fluff: if removing a node loses nothing, remove it.

## Notes are specifics, not descriptors

A note earns its place only if a practitioner would use it while doing the work: a template, a script, criteria, a rule for when to stop, a definition the title depends on, the options to choose from. Never write a note that explains, summarizes or justifies a branch ("New customers come from an engine that…," "Growth isn't the first sale," "Strategic choices"). If the title needs a paragraph to make sense, rewrite the title. Most branch nodes need no note at all.

## Cover the work practitioners actually run

Strategy branches must reach the tactics a practitioner would recognize and run. A branch about getting customers that never names search, AI answers, paid search, paid social, organic social, content, creators or earned media is incomplete, however sound its strategy. Name each tactic as its own branch, start it with what makes that channel work, and break it down like any other job.

## No arbitrary numbers

Never write a count, duration or threshold that only sounds precise ("talk to five customers," "for two weeks," "the last 90 days," "pull 50 reviews"). Replace it with the rule that decides the number:

- Interviews and research: "until new ones stop surfacing new themes," "until the same triggers keep coming up."
- Data windows: "a full year, so seasonal swings show," "recent enough to remember the day they started looking."
- Test length: "at least one full buying cycle," "until each group is big enough to compare."
- Cadence: "each reporting cycle," "on a regular schedule."

A number may stay only when it is a definition (the 1 to 4 rating scale, a five-second test, star ratings), part of the structure being described (two test groups, numbered survey questions), or a widely used benchmark named as one ("a widely used bar is 40%").

## Writing style

Plain verbs, sentence case, no em dashes, no buzzwords. Spell out an acronym the first time with its meaning in parentheses. Keep titles under about 12 words; put everything else in notes.

## Common failures and the fix

| Failure | Fix |
|---|---|
| A leaf reads like a question or instruction ("Screen with one question") | Lift it into the task that contains it ("Write the screener") and move the detail to its notes |
| A branch jumps from strategy to minutiae ("Write your growth model" → "Count customers by type") | Add the missing middle jobs: define, pull data, build, read, decide |
| A leaf is still a project ("Audit channels") | Break it into the jobs a practitioner would actually schedule |
| The branch explains how to be good at something but not how to make it happen ("Be easy to remember" under Acquisition) | Start the branch with the core mechanic (where customers come from, which engine to build) and put the supporting bets after it |
| A branch stays at strategy and never names the tactics ("Choose the engine" with no SEO, ads or creators under it) | Add a branch per tactic practitioners run, each broken down to schedulable tasks |
| A node is vague ("Win one door first") | Rename it so the meaning is in the title ("Sell where customers already buy") and define the term in the note |
